### Primary source facts and qualification scope

Kind v0.33.0's base-image Dockerfile selects containerd v2.3.4.
Its archive loader uses ctr import --all-platforms --digests, so reference/import details are part of the profile.
Containerd v2.3.4 stores the config digest separately and normally publishes a selected stored repository digest as CRI ContainerStatus.ImageRef.
Kubernetes v1.36.4 deliberately publishes that ImageRef as Pod ContainerStatus.ImageID.
This source chain supports the proposed direct configured-reference comparison, but containerd selects the first stored repository digest and aliases can change its exact representation.
The selected actual node binary/import path and native helper Pod behavior still require positive qualification.

The existing private M7 artifact metadata distinguishes digest/index, selected manifest_digest, config image_id, platform and loaded_digest.
The inspected legacy-only inventory has null native-runner entries and its prepared receipt has no native-runner role; it proves no native image/profile clearance.
Its existing verify_loaded path validates loaded manifest to config to platform and is reusable under a separately assigned native qualification lease.
Do not reuse its bootstrap-only permissive imageID matching as production native admission.
