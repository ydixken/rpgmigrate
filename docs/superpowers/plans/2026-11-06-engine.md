# Engine Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the delegated team execution.
> Use superpowers:executing-plans inside each assigned worker task.
> Track each step with a checkbox.

**Goal:** Build the complete approved migration engine, beginning with real libpq connections, raw COPY, and safe native state.

**Architecture:** Use one Cargo package with a thin executable and private modules.
Rust owns migration state and scheduling.
A narrow libpq boundary owns connections, results, and COPY buffers.

**Tech Stack:** Rust, native libpq, PostgreSQL utilities, and a persistence backend selected by correctness tests and benchmarks.

**Spec:** [Approved design](../specs/2026-11-06-rpgmigrate-design.md).

## Global Constraints

- The executable is `rpgmigrate`.
- The baseline is `ydixken/pgcopydb` at `86bf908adca02d87063849dae775a02c1659c829` on `origin/v0.18-fixes`.
- Use ordinary branches in the primary checkout, never worktrees.
- Never import, resume, restart, convert, delete, or clean legacy pgcopydb state.
- Preserve PG9.6/test_decoding, Timescale PG13, the PG16-18 suite, and the approved operator compatibility matrix.
- The default durability profile is `durable`.
- `relaxed` requires explicit finite `--loss-max-transactions` and `--loss-max-bytes` values.
- The default `--apply-jobs` value is `1`.
- COPY and schema completion are durable in every profile.
- Every successful normal completion proves a complete durable target prefix.
- The leader reviews this plan before implementation.
- Commit only after checks exist, pass, and the leader requests a commit.

## Review Focus

- A symlink or directory replacement during restart must fail without changing foreign files (E1).
- A COPY error after its last data buffer must fail and roll back target changes (E1).
- A lost COMMIT response must resolve through the fenced target PRIMARY checkpoint (E3).
- Concurrent databases must share one durable risk budget, including reservations whose workers die (E4).
- A target trigger can affect another table or an external service (E3 and E7).

## Shared contract section

The leader accepted these E0/E1 interfaces and review clarifications.
Change them only through leader coordination.
The integration worker owns their declarations.
All plain contract types and fields below use `pub(crate)` visibility, including tuple fields in `Environment` and `CommandPath`.
`Conninfo` keeps its inner `CString` private and exposes only the listed accessor.
Transport handles and `NativeState` remain opaque with private fields.
All modules and methods below are crate-private unless stated otherwise.
The library exposes one binary entrypoint, `pub fn run() -> u8`, in `src/lib.rs`.
It constructs `Environment` and `IoControl` for the thin binary in `src/main.rs`.
Crate-local tests can construct both plain structs directly.

### `src/contracts.rs`

```rust
type Result<T> = std::result::Result<T, Error>;
struct Error { kind: ErrorKind, message: String }
enum ErrorKind {
    BadArgs, BadConfig, BadState, Pgsql, Pgctl,
    Source, Target, Reload, Internal, Fatal,
}
impl Error { fn exit_code(&self) -> u8; }
struct Conninfo(std::ffi::CString);
impl Conninfo {
    fn new(value: std::ffi::OsString) -> Result<Self>;
    fn as_c_str(&self) -> &std::ffi::CStr;
}
struct IoControl {
    deadline: std::time::Instant,
    cancelled: std::sync::Arc<std::sync::atomic::AtomicBool>,
}
struct RunId([u8; 16]);
struct QualifiedTable { schema: String, table: String }
enum CopyFormat { Text, Binary }
struct CopyTable {
    name: QualifiedTable,
    columns: Vec<String>,
    format: CopyFormat,
}
struct CopyPlan { tables: Vec<CopyTable>, buffer_bytes: usize }
struct CopyReport { tables: u64, rows: u64, bytes: u64 }
enum StateAction { Create, Resume, Restart }
struct StateRequest {
    path: std::path::PathBuf,
    action: StateAction,
}
struct StateIdentity {
    run: RunId,
    canonical_path: std::path::PathBuf,
    format_version: u32,
}
```

`Error::exit_code` maps the variants above to `1, 2, 3, 4, 5, 6, 7, 9, 12, 122`, respectively.
Success and requested help/version use `0`.
`message` contains only redacted diagnostics.
`Conninfo` uses redacted `Debug` and has no secret-bearing `Display` implementation.
Only the transport boundary uses `as_c_str` to pass connection settings to libpq.
Use checked arithmetic for byte and row counters.
E1 uses an absolute `IoControl.deadline` with a 300-second whole-command limit and an 8 MiB COPY forwarding/write budget.
The deadline does not reset between operations.
The forwarding budget does not cap process RSS because libpq allocates complete COPY rows, including the fixture's 9 MiB row.
These are first-slice restrictions, not production/full-migration compatibility defaults.
Replace them with configurable operation/stall budgets before production qualification.

### `src/pg/mod.rs`

```rust
struct PgConnection;
struct PgResult;
struct CopyBuffer;
impl PgConnection {
    fn connect(conninfo: &Conninfo, io: &IoControl) -> Result<Self>;
    fn query(&mut self, sql: &str, io: &IoControl) -> Result<PgResult>;
    fn start_copy_out(&mut self, sql: &str, io: &IoControl) -> Result<()>;
    fn read_copy(&mut self, io: &IoControl) -> Result<Option<CopyBuffer>>;
    fn start_copy_in(&mut self, sql: &str, io: &IoControl) -> Result<()>;
    fn write_copy(&mut self, data: &[u8], io: &IoControl) -> Result<()>;
    fn finish_copy_in(&mut self, io: &IoControl) -> Result<u64>;
    fn abort_copy_in(&mut self, reason: &str, io: &IoControl) -> Result<()>;
    fn quote_identifier(&mut self, name: &str) -> Result<String>;
}
impl PgResult {
    fn rows(&self) -> usize;
    fn cell(&self, row: usize, column: usize) -> Result<Option<&[u8]>>;
    fn command_tag(&self) -> Result<&str>;
}
impl CopyBuffer { fn as_bytes(&self) -> &[u8]; }
fn ping(conninfo: &Conninfo, io: &IoControl) -> Result<()>;
fn validate_conninfo(conninfo: &Conninfo) -> Result<()>;
fn libpq_version() -> i32;
```

The implementation uses `PQconnectStart`/`PQconnectPoll` and readiness polling with a deadline.
Keep connections and results thread-confined.
Do not implement `Sync` for them.
Copy error strings before freeing their owners.
`PgResult` releases with `PQclear`, `CopyBuffer` with `PQfreemem`, and the connection with `PQfinish`.
`read_copy` returns `None` only after draining and validating the final source result.
`finish_copy_in` drains all results and checks `PGRES_COMMAND_OK` and the COPY row count.
`query` drains the connection before returning its single checked result.
Reject accidental multi-statement use in this narrow interface.
Bound query results by using small queries and paged catalogs.
Use SQL parameter APIs for data values when E3 adds CDC apply.

### `src/state.rs`


Create version `1` manifests with magic `RPGMIGRATE`, a random run identity, and canonical directory identity.
Hold an OS lock and directory handle through mutation.
Check ownership and directory identity again before publication or cleanup.
Use private file modes, atomic manifest publication, and file plus directory synchronization.
Foreign nonempty directories, mixed state, symlinks, and detected identity replacements fail without cleanup.
Require exclusive control of the private `0700` directory while the run is active.
Permissions and advisory locks cover other users and cooperating rpgmigrate processes.
Arbitrary noncooperating mutation by the same user is outside this boundary because POSIX validation and rename do not provide compare-and-swap publication.
E1 refuses native resume/restart after identity checks because recovery is an E3 deliverable.
E1 never treats a local COPY marker as authority to reuse target data.
Open native state before the first database connection and retain its lock through COPY.
E1 requires an existing parent directory and refuses all prior runs, including completed ones.

### `src/catalog.rs` and `src/copy.rs`


E1 implements `ping` and a restricted, truthful `copy table-data` path for all eligible tables in one database.
Use one source REPEATABLE READ READ ONLY snapshot and serial raw text COPY into precreated compatible empty logged tables.
Hold source ACCESS SHARE locks while allowing concurrent source data changes outside the snapshot.
List writable columns explicitly and quote identifiers through libpq.
Check all target tables before the first target write.
Refuse unsupported table shapes, filters, follow, binary COPY, splitting, and unimplemented options before mutation.
Reject source or target RLS and user triggers before any target mutation.
Require the built-in heap table access method on both ends.
Reject target CHECK and exclusion constraints and expression or partial indexes before mutation because their functions can alter session settings or other tables.
Allow only the six built-in index access methods (`btree`, `hash`, `gist`, `gin`, `spgist`, `brin`) and matching `pg_catalog` operator classes, with access-method and operator-class OIDs below 16384.
Reject custom table/index access methods and operator classes.
Require each target foreign key to be deferrable, reference a parent inside the validated COPY set, use identical built-in column types, and use built-in `pg_catalog` comparison operators with OIDs below 16384.
Defer supported foreign keys with `SET CONSTRAINTS ALL DEFERRED` before loading data.
Validate them with `SET CONSTRAINTS ALL IMMEDIATE` before the final durability check and COMMIT.
Reject nondeferrable foreign keys until safe ordering is implemented and tested.
Require target `SHOW session_replication_role` to report `origin` without adding permission to change it.
Reject target internal constraint triggers unless `tgenabled` is `O` or `A`; otherwise deferred validation could silently omit their checks.
Source CHECK constraints and indexes are not executed by COPY TO and do not require these target-only refusals.
Reject unsupported table or column shapes in this preflight rather than skipping them.
E6 owns the later supported semantics for these cases.
Require UTF8 server encoding on both ends for E1.
E6 owns other encodings.
Before planning and COPY, pin both sessions to the following values.

- `DateStyle = ISO,YMD`
- `IntervalStyle = postgres`
- `TimeZone = UTC`
- `extra_float_digits = 3`
- `bytea_output = hex`
- `row_security = off`
- `client_encoding = UTF8`
- `search_path = pg_catalog`

Check every effective value after setting it.
PostgreSQL documents RLS, trigger, and text format behavior in its [COPY reference](https://www.postgresql.org/docs/14/sql-copy.html).
Preserve their fixtures and E5/E6 tasks rather than claiming parity.
Source tables with zero rows are valid.
Zero discovered tables require an explicit verified empty plan, not a swallowed catalog error.
Use one synchronous target transaction across every table in the bounded E1 slice.
Retain target SHARE ROW EXCLUSIVE locks from preflight through final COMMIT, because releasing them would allow table-definition or data changes after validation.
Require schema and namespace DDL quiescence in both databases throughout COPY.
Table locks do not prevent `ALTER SCHEMA RENAME` or equivalent namespace replacement.
Source DML remains permitted under the consistent snapshot.
Target DML waits for the retained target locks.
The COPY coordinator owns both transaction lifecycles.
Later full-scale work requires per-part checkpoints before relaxing this single-transaction restriction.
Later identity and DDL coordination must address namespace changes before removing the quiescence requirement.
Roll back known failures before COMMIT dispatch.
After COMMIT dispatch, a lost response means an unknown outcome and provides no proof of rollback.
Forward COPY buffers without decoding rows.
Allow one oversize row while accounting for its bytes, libpq buffers, and socket buffers.
Release each consumed buffer before reading the next under backpressure.
Record completion only after every source result and target COMMIT succeeds.
Unknown COMMIT returns a nonzero uncertain-state failure in E1.
Use `BadState` with the diagnostic code `commit-outcome-unknown` and never publish the run's completion marker.
E3 adds checkpoint-based recovery.
